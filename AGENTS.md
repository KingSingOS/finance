# Project working practice

Read `.solo-build/README.md` for the shared delivery practice and `.solo-build/adoption.json` for current mapping gaps. Establish the actual user outcome, source revision, owner, allowed paths, relevant checks and recovery plan before changes.

Use the project's existing task/decision records. Missing tracker or profile information stays unresolved until established; generated configuration is not product acceptance. Preserve existing work. Use one integrator for shared writes and bounded independent helpers when authorized and useful.

Run meaningful native checks and inspect their real results; skipped/zero checks are not success. Bind review evidence to the current revision. Give the owner a before/after use case, actual evidence, risks and exact decision. Merge and release authority remain separate.

Record failures and changed-state resume triggers. Improve skills through a versioned candidate, baseline and held-out evaluation, independent review and rollback. Configure code intelligence and external model providers only within explicitly permitted source/data scope. No credentials, indexing, installation, deployment or scheduled worker is enabled by this file.
